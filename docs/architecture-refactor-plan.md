# 架构与布局重构计划

基线与现状见 [架构地图](architecture-map.md)。P0 文档已完成；P1 已在工作分支实现，验证状态见文末。P2–P5 尚未实施。使用“需求—规则—验收”组织，每阶段形成可独立审阅的 feature PR，沿用仓库 CI。

## 审查校准

前轮的“12 类已确认”混合了源码事实、历史截图和推断。这里以当前 main 为准保留问题，但校准结论强度：

| 原发现 | 证据与边界 | 对应阶段 |
| --- | --- | --- |
| 小屏/大字裁切 | 固定 48dp 高度预算和最低板高已确认；实际裁切/压缩位置需设备测量。不是无条件 P0 | P2 |
| 文字题上下分散 | 空的 weight 信息区、底部选项已确认，历史实测图支持 | P2 |
| 和弦图小、旋转不改外层布局 | 固定底部板区与图形等比缩放已确认，历史图支持 | P2 |
| 示例页纵向堆叠 | 横屏页使用普通纵向框架、图前说明、图后试听已确认 | P2 |
| 顶栏空占位 | 下一题 100dp 常驻占位已确认；具体溢出需尺寸/字号复现 | P2 |
| 指板目标在屏幕外 | 横向滚动且无任务定位已确认；浏览全指板是设计的一部分，不得统一自动滚到隐藏答案。认音可定位公开题面标记，找位只能用公开范围导航 | P3 |
| 指板触点小 | 禁用最小触点扩展与弦高计算已确认；不得简单扩触点导致相邻弦重叠。原 13dp 仅是最低板高假设下的计算，不是实测误触率 | P3 |
| 大字显示 | 和弦 sp 随字号变而几何固定；NotationView 原生字用 dp，实际不随系统字号增长。二者问题不同；旧报告称谱面全用 sp 不准确 | P3 |
| 短谱压缩 | Pilot 直接 fillMaxWidth，普通谱面按内容宽度滚动，差异已确认；密度影响需审图 | P3 |
| 深色主题 | ChordDiagram 固定浅色背景/深色文字已确认；改善归为主题一致性，不假称对比度已经测量失败 | P3 |
| 普通页面宽屏与长列表 | 强制竖屏/单列无最大宽度已确认；无性能测量，不认定卡顿。“46 节点”来自声明匹配计数，不作为真实运行节点总数 | P4 |
| 单选与无障碍 | 指法/专项文字不接点击、和弦 Canvas 无逐位置动作已确认 | P3/P4 |

另有架构证实问题：业务依赖显示标记记录暴露、输入资格依赖 UI 投影、导航残留不可达专项、音频状态未显示、根音白环契约未消费。分别进入 P1/P2/P4，不能靠布局改动悄悄改变业务。

## P0：现状与维护入口（本批完成）

- 需求：后续需求能够定位当前源码，不误改 legacy。
- 规则：记录实际依赖、运行入口和例外；纠正 ChordDiagram 入口；规划与已完成事实分开。
- 验收：架构地图覆盖页面、课程、自适应、证据、存储、音频、共享/legacy、构建与测试；README/AGENTS 互链且本地路径有效。
- 依赖无；难度低；收益高。不改 App 版本或交付 APK。

## P1：隔离会影响学习证据的显示依赖

- 需求：改颜色、标记文字和布局，不改变知识暴露与输入资格。
- 规则：提取纯业务的展示/暴露事实和交互策略（名称待实现时确定）。CorrectionPresentation、TrainingUiAdapter 和 ViewModel 消费同一事实；业务不再根据 UI label、MarkRole 推断学习证据。不复制判题或开放范围算法。
- 验收：同任务/输入下，重构前后首答、暴露、逐成员记录、听辨门槛一致；隐藏答案不进入独立题显示状态；错误坐标、旧 taskId、忙碌/前后台/播放中事件仍受拒绝。运行相应 contracts、audio integration、evidence/recovery 测试。
- 依赖 P0；难度高；收益极高。可以先做不改变效果的提取，再修改 UI。

## P2：拆页面连接与题型布局

- 需求：文字题集中答题，和弦图与操作相邻，谱面和指板主次明确，小横屏/大字可用。
- 规则：LearningApp 保留状态、路由、生命周期、文件选择器；提取普通页面框架。TrainingScreen 分派到文字、指板、和弦、谱面布局；共享顶栏/选项/反馈，不复制整套业务。按实际测量分配空间，明确最小可用高度与滚动回退；以“同题提示/纠错不跳动”稳定板区，不以所有题型统一高度为目标。
- 规则：和弦竖图在横屏使用左右布局，横图依据剩余宽高重新布置；说明按需展开。音频失败/静音提示进入既有显示契约可见区域。保留重听、辅助认定、自动下一题、返回提交时机。
- 验收：至少覆盖纯文字无说明/有说明、七选项、长标题、首教/独立/纠错/已纠正、和弦两方向/图例、关系题、短谱与创作；640×320 与常规宽横屏、1.0/1.3/2.0 字号检查无截断、主要操作可达。尺寸为验证样例，不是新增全局门槛。
- 依赖 P1（涉及显示/交互语义时）；难度中高；收益极高。

## P3：指板、和弦、谱面可用性

- 需求：看得清、点得准、滚动可理解，主题和辅助字号一致。
- 规则：视觉和命中共用几何；最小弦间距与可视范围一起设计，不靠重叠触点补救。公开题面标记可定位；隐藏答案不传入组件、不通过滚动暴露。优先保留用户浏览状态，并给离屏公开目标明确入口。
- 规则：统一短谱和普通谱的内容宽度策略；原生谱面字与几何成套缩放。和弦标题/标签预留测量空间，颜色取主题；核对 rootRing/dot 指法语义后修复契约落空。补和弦逐位置语义、可答/试听状态和等价操作。
- 验收：0–4、0–8、0–12/15 指板；高品与空弦；横/竖开放和弦/横按；四主题/大字；滚动跨题、点击边界、读屏操作、根音说明与图一致。截图审阅和几何测试同时用；误触舒适度需真机反馈。
- 依赖 P1/P2；难度中高；收益高。

## P4：普通页面与导航一致性

- 需求：首页至设置的信息主次清楚，宽屏不过度拉长，显示能力与入口一致。
- 规则：普通框架加合适的内容宽度/回流策略，长列表按实际规模选择惰性布局；设置单选整行响应。核对专项无入口、分类分支、能力详情与历史跳转；恢复专项入口属于产品行为变化，不因发现死回调自动开放。
- 验收：首页、三分组、知识树、详情、历史、设置、短谱菜单的空/有数据/锁定/忙碌状态；手机与宽屏、辅助字号、返回栈、备份对话框。能力详情显示与实际开始节点对应。无性能测量不宣称列表优化收益。
- 依赖 P0，框架改动跟随 P2；难度中；收益中高。

## P5：按需求分离副作用与遗留清理

- 需求：后续改音频、备份或数据校验能局部测试，删除代码有依据。
- 规则：ViewModel 保持提交协调入口，按生命周期提取短谱播放/计时或备份协作者；短谱输出可注入。Repository 可分接口、codec、Room 文件，但不改 schema/字段。契约纯值按使用者归属整理，不为文件整齐引入不必要映射。
- 规则：先列引用再清理不可达 ChordOverlay 与旧页面/测试；保留 FretPosition 等仍用兼容依赖。无需立即拆 Gradle 模块或批量搬包。
- 验收：旧快照/暂停题/事务失败/覆盖升级、首播/取消/陈旧回调都保持；当前入口与共享能力无回退。删除清单逐项可追溯。
- 依赖 P1，按后续具体改动选择执行；难度高；收益按需求评估。不是本轮文档提交自动触发的全库重写。
